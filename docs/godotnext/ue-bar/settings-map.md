## NextGI (Lumen)

Hardware ray tracing for a Lumen row means the project settings **Support Hardware Ray Tracing** and **Use Hardware Ray Tracing when available**, both enabled ([Lumen GI, 5.9][lumen59]; the same names as 5.8). The 5.9 page adds that new projects enable Support Hardware Ray Tracing. The [console-variable reference][cvars59] prints `r.Lumen.HardwareRayTracing` with default 0, described as using hardware ray tracing when available and falling back to software otherwise. The comparison enables the two project settings. It does not treat that cvar's default of 0 as "on".

Two UE 5.9 settings hold for every hardware ray tracing row (**UE 5.9 Preview**):

- **Hardware Ray Tracing Mode** stays at **Full** on Windows. It is in Project Settings > Platforms > Windows, Renderer section, and Linux has the same setting. The [Lumen World Cache page][worldcache59] prints Full as "the default"; the [ray tracing performance guide][rtperf59] lists Disabled, Inline, Simplified Material and Full under Platforms > [Platform]. Inline and Simplified Material remove Lumen hit lighting. The [archived 5.8 guide][wb-rtperf58] called this per-platform setting Ray Tracing Mode, with Disabled, Inline and Full. No page prints the setting's options or default for Mac, so the M5 Max rows do not name it; #229 records it there.
- **Lumen World Cache** stays off, the UE 5.9 default ([Lumen World Cache][worldcache59]: "The World Cache is off by default."). It turns on only with `r.Lumen.WorldCache.Supported=1` in `DefaultEngine.ini`, applies only when Lumen uses hardware ray tracing, and replaces the Surface Cache while active. Its GPU time is reported as LumenWorldCache in `stat gpu`. The page carries no Experimental or Beta banner. GodotNext has no counterpart; whether it enters v1 scope is a plan decision for the lead.

The Lumen total, where a row names it, is the sum of the three `stat gpu` passes the [performance guide][lumenperf59] prints: **Lumen Scene Lighting**, **Lumen Screen Probe Gather** and **Lumen Reflections**. This is the same as 5.8; with the World Cache off, no fourth pass joins. The guide recommends `r.Lumen.AsyncCompute 0` to measure Lumen on its own; #229 sets it in the comparison's `exec_cmds` (2026-11-15), so the three passes are not timed under async overlap, and the report checks the value each run echoes. The lead can reverse this. The game-mode capture on the RTX 4080 SUPER (2026-11-15) shows no single column for the sum. Until #229 step 2 writes the columns into this record and §23.5, the kitbash comparison config sums the three observed columns `GPU/LumenSceneLighting`, `GPU/LumenScreenProbeGather` and `GPU/LumenReflections`.
