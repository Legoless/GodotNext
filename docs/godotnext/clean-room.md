# Clean-room packet

GodotNext implements Lumen-class global illumination (NextGI) and
Nanite-class geometry (NextGeo) from public sources only. This packet is
the working record for plan §19 (Legal, naming, and clean-room protocol)
and §17 item 12. It is an engineering control, not legal advice (§19):
obtain counsel before a commercial release or before accepting code from
anyone with access to proprietary engine source.

Names: systems ship as NextGI/NextGeo. "Lumen-class"/"Nanite-class" are
descriptive comparisons for internal planning only; nothing implies Epic
affiliation or compatibility.

## Approved inputs (§19)

Project-approved study inputs are:

- Public papers, official public documentation, and conference talks.
  This includes public Unreal Engine 5.8 and 5.9 documentation and
  release notes, and Epic/SIGGRAPH talks (Lumen 2022, MegaLights 2025).
- Observed editor behavior and debug views. Running the Unreal Engine
  5.9 editor and packaged builds for the performance comparison counts
  here (the plan targets UE 5.9 since v3.6, §25): Unreal Engine is used
  only as a black-box binary, it is never built from source, and Unreal
  Engine projects stay outside this repository (§23.7).
- Permissively licensed source whose license has been recorded,
  including Khronos, Apple and Microsoft specifications and samples with
  recorded licenses.

If the license of a candidate input is not recorded, the input is not
approved yet. Record it first (vendoring gate below), then read it.

## Forbidden inputs (§19, v2.4)

Never open, read, search or copy from:

- Unreal Engine source or shaders, including the `Engine/Source`,
  `Engine/Shaders` and plugin `Source` folders of an Unreal Engine
  install.
- NvRTX, NVIDIA's Unreal Engine branch. It is Unreal source.
- Any Unreal Engine plugin source, including NVIDIA's Unreal Engine
  DLSS plugin source.
- NVIDIA's DLSS sample and Donut source (separate pre-release license).
- Any NVIDIA or other proprietary SDK source under terms incompatible
  with MIT. The only exceptions are the NGX inputs listed in §19,
  "Proprietary runtime SDKs" clause (c); the SDKs themselves are never
  committed to this repository.
- Copied constants or tables, decompiled binaries, and code generated by
  prompting a model to reproduce any of the above.

## Proprietary runtime SDKs

The license records for the proprietary runtime SDKs — NVIDIA DLSS/NGX,
Streamline, and the NVIDIA-RTX/godot study input — live in
[`docs/godotnext/dlss-license.md`](dlss-license.md), written by the DLSS
license packet task (#98). No license terms are restated here. Until that
record lands, §19 clauses (a)–(k) in the plan govern, and no DLSS SDK
header is read for implementation.

## Contributor rules

- **Separation.** A contributor who has recently read relevant
  proprietary source writes behavior and specification notes from public
  sources for that subsystem, not implementation code.
- **Source log per subsystem.** Each subsystem keeps a log of the inputs
  it was actually built from: the paper, document, talk or licensed
  source (with URL and license), the date, and who consulted it. If it is
  not in the log, it was not an input.
- **Exposure.** Anyone who realizes they have seen a forbidden input for
  the subsystem they are implementing stops, notes it in that
  subsystem's source log, and tells the lead before writing more code.
- **Vendoring gate.** Every third-party file merges only after its
  upstream URL, version or commit, license text, modifications and
  NOTICE placement are recorded under Godot's third-party conventions
  (`thirdparty/README.md` and `COPYRIGHT.txt`), before merge.
- **No SDK files.** NVIDIA SDK headers, libraries and runtimes are never
  committed, in any directory.
- **Assets.** Test scenes use original or CC0 content with recorded
  provenance. No Mixamo or marketplace assets, and no demo assets from
  proprietary engines.

### COPYRIGHT.txt audit

Checked for this packet: every directory under `thirdparty/` was
compared with the `Files:` entries in `COPYRIGHT.txt`. meshoptimizer
and SPIRV-Cross have explicit entries (above), so this packet makes no
`COPYRIGHT.txt` change. Three imported directories have no explicit
entry and fall under the file's global `Files: *` entry instead:
`thirdparty/linuxbsd_headers/`, `thirdparty/re-spirv/` and
`thirdparty/smaa/`. That is upstream Godot's state at the import commit,
and the `COPYRIGHT.txt` header states third-party details are
summarized; it is recorded here for the lead to judge, not edited by
this packet.
