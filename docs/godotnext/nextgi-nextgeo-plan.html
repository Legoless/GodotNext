1. Goal

Make GodotNext capable of dynamic, high-fidelity 3D scenes that today force a choice of Unreal Engine: dense source geometry without manual LOD chains, and moving lights/emissives/geometry with stable multi-bounce indirect light and glossy reflections.

Version 2.2 revision record: this revision applies the post-v2.1 C++ verification pass (Claude Opus + Agy) and live SSH hardware audit to Version 2.1, closing the remaining paper defects before Phase 0 starts: (1) Forward+ load/clear & frame order: removes RD::DRAW_IGNORE_ALL (which maps to ATTACHMENT_OPERATION_IGNORE → ATTACHMENT_LOAD_OP_DONT_CARE and discards velocity on tile GPUs), forces the depth + normal-roughness prepass, skips render_forward_clustered.cpp:2327-2330’s motion-only clear when virtual geometry drew, runs Step 7 PASS_MODE_COLOR with load_color = true (RD::DRAW_DEFAULT_ALL), places SSAO/SSCS/SSR in Step 3b between Stage A guides and Stage B resolve, gives NextGI its own call site after update_light_buffers() and bake_cluster(), dispatches shadow-view cluster culling before _render_shadow_begin, and snapshots prev_transformed_aabb at dirty-event time before _update_instance overwrites it; and (4) Fleet & vertical-slice staging: records live hardware — local Apple M5 Max (40-core GPU, 128 GB RAM) as daily development + Metal correctness gate, RTX 4080 SUPER machine (Windows 11, i9-12900KS, 64 GB RAM, NVIDIA RTX 4080 SUPER Vulkan 1.4.357 + Intel UHD 770 non-RT fallback) as the named performance/HWRT/D3D12 gate host with calibrated Ada ms ceilings, and Linux VM (4-vCPU EPYC VM, Mesa llvmpipe) as Linux CPU/software-Vulkan smoke host — and splits P0 into P0a → P1 → P4 (NextGI vertical slice first) ahead of P0b → P2 → P3 (NextGeo runtime) for solo + AI-agent execution. No engine implementation has started.

In scope for the program

  • NextGeo: offline cluster hierarchy, GPU cut selection, on-demand page streaming, visibility-buffer material resolve, shadow/RT proxy generation.
  • NextGI: screen traces, Surface and World Radiance Caches, software-SDF and post-v1 hardware-ray-traced tiers, probe far field, denoised diffuse and specular indirect light.
  • Shared editor import, debug views, profiling, test scenes, capability gating, and legacy fallback.

Explicit non-goals for v1

  • Not a source port of Epic code and not binary/behavioral parity with Unreal Engine 5.8 in every scene.
  • No skinned characters, arbitrary custom shader displacement, transparent/foliage-card coverage, Mobile, Compatibility, or Web support.
  • No MegaLights-class many-shadow-light solver, Substrate-class material system, PCG/world-partition system, or console work in the first release.

The strategic objective is a renderer we can maintain under Godot’s MIT license, built from public papers/docs and inspected open implementations where the license permits. That constraint shapes the design as much as GPU performance does.

3. Verdict and v1 scope

Forward+ already contains useful scaffolding — a thin depth/normal-roughness prepass, clustered light buffers, compute/indirect submission, and a Vulkan ray-tracing backend (modulo a TLAS device-address bug fixed in P0) — for a compute-driven visibility-buffer NextGeo and hybrid NextGI.

It does not contain the other prerequisites: persistent GPU scene, GPU cluster Hi-Z/culling, mesh/task shader stages, cross-driver ray tracing, geometry paging, a unified GPU material-binding/resolve model, virtual shadows, or a real-time denoiser.

Honest v1 cut: static opaque StandardMaterial3D content, Forward+ (forward_plus) only, Vulkan-class desktop hardware first. Everything outside that envelope stays on the current forward path and existing GI tiers.

4.2 GPU-driven substrate: present vs absent

Present

  • Compute dispatch and compute-indirect; indexed indirect draws (currently centered on MultiMesh).
  • Driver-level indirect-count wrappers on Vulkan/D3D12, not yet exposed through RenderingDevice/graph or enabled via Vulkan 1.2 device features.
  • Clustered light assignment buffer; normal/roughness, velocity, specular buffers in relevant modes.
  • RenderingDevice BLAS/TLAS, hit SBT, RT pipeline and ray-query APIs, with a non-Apple Vulkan backend whose acceleration_structure_instance_write currently passes buffer_get_device_address instead of vkGetAccelerationStructureDeviceAddressKHR (fixed in P0).
  • Feedback-driven texture mip streaming as an architectural template for geometry paging.

Absent

  • TASK/MESH shader stages and vertex-less pipelines; pipeline creation still requires a vertex stage.
  • GPU instance/cluster culling and two-phase occlusion (a GPU depth pyramid already exists for SSR; cluster occlusion does not), GPU LOD choice, persistent GPU scene.
  • Per-cluster vertex data, cluster DAG, geometry page cache, and residency feedback.
  • Unified GPU material/texture resolve path (neither an RD bindless descriptor table with deferred-free lifetime nor per-material classified compute resolve exists).
  • Real-time denoiser, persistent SVGF guides/history, virtual shadow-map paging.

4.5 Existing geometry path

  • ArrayMesh LODs are index-only simplifications that share full-resolution vertex buffers, so they save raster triangles but not vertex memory or streaming bandwidth.
  • ImporterMesh::generate_lods() already uses meshoptimizer attribute-aware simplification and is the correct import hook for a cluster DAG builder. It simplifies whole surfaces today; it does not group clusters, lock group borders, or propagate parent error.
  • The vendored meshoptimizer module compiles clusterizer/partition/simplifier sources, but only simplification-related function pointers are wired into SurfaceTool. Meshlet construction APIs are present yet unused.
  • mesh_add_surface eagerly uploads all vertices/attributes/skins/indices/LOD indices. There is no page-fault, priority, VRAM-budget, or upload-queue API for geometry.
  • Occlusion culling is CPU HZ/AABB and baked occluders, not a GPU depth pyramid produced from the previous rendered frame.
  • create_shadow_mesh() is the precedent for an always-resident position-only proxy (queried via MeshStorage::mesh_get_shadow_mesh and cached once per surface into GeometryInstanceSurfaceDataCache::surface_shadow inside RenderForwardClustered::_geometry_instance_add_surface_with_material), not a per-view scene-cull selector, raster fallback, or BLAS source today.

GPU instance record: current/previous transform, current and dirty-event-snapshotted previous world AABBs (transformed_aabb and prev_transformed_aabb; note RendererSceneCull::_update_instance overwrites Instance::prev_transformed_aabb at renderer_scene_cull.cpp:1772, 1945, so the pre-move box must be captured when the dirty event fires), mesh/page-table index, per-surface material override indices and eligibility mask, per-instance SRC page-table handle, layer mask, cast-shadow mode, GI mode, lightmap instance data, skeleton presence (exclusion trigger), instance shader-uniform presence (exclusion trigger in v1), and double-precision handling. This mirrors the real instance inputs in scene cull; a single material-override index is insufficient.
  3. Exclusive dispatch rule (frozen in v2.1 — per (instance, surface, view)): virtual data is an optional payload attached to the existing ArrayMesh mesh RID — there is no second mesh RID and no new instance base type. Dispatch is decided per (instance, surface, view), not whole-instance, so multi-surface meshes mixing opaque StandardMaterial3D surfaces with glass/alpha/custom-shader surfaces render eligible surfaces through virtual cluster cuts while keeping excluded surfaces on the legacy forward lists without dropping or double-drawing either. Concretely, RendererSceneCull retains instance culling/lists, while renderer-side surface caching and pass-list population in RenderForwardClustered (_geometry_instance_add_surface_with_material and GeometryInstanceSurfaceDataCache::surface_shadow, where MeshStorage::mesh_get_shadow_mesh is cached once per surface rather than selected per-view in RendererSceneCull) suppress legacy main-pass, discrete-LOD, and surface_shadow submission whenever virtual cuts handle that (instance, surface, view). MultiMesh and particle consumers (INSTANCE_MULTIMESH, INSTANCE_PARTICLES) ignore VirtualGeometryData in v1 with a counted editor warning; GridMap octant MultiMesh cells follow that rule, whereas GridMap::make_baked_meshes registers standard RSE::INSTANCE_MESH instances that either route per-surface through NextGeo when unlightmapped or stay cleanly on the legacy lightmapped path using preserved ArrayMesh UV2 data.
  4. Material record: supported StandardMaterial3D fields, texture/material-bucket indices (supporting both Option A bindless tables and Option B classified dispatches until P0b freezes one), UV transforms, feature flags, alpha mode, fallback reason. Texture residency must cooperate with existing texture storage/streaming.
  5. Cluster record: sphere/cone bounds, parent/child range, geometric+material error, page ID, vertex/index offsets, surface/material ID, resident flag.
  6. NextGI outputs: reuse RB_TEX_AMBIENT and RB_TEX_REFLECTION initially through a dedicated post-bake_cluster NextGI entry point (keeping legacy SDFGI/VoxelGI at gi.process_gi() line 1681); define energy scale so volumetric fog and forward lighting do not double-count SDFGI/VoxelGI/SSIL.
  7. Fallback reason enum: one shared enum used by import, editor inspector, runtime stats, and tests (unsupported driver, alpha, skinning, custom vertex/fragment feature, instance uniforms, lightmapped instance, MultiMesh/particles, missing page, material feature, platform tier).

7. NextGeo design — Nanite-class virtual geometry

7.1 Offline DAG builder

  1.   3. Group and simplify: partition adjacent clusters into groups; simplify each group with attribute-aware simplification while locking group borders; re-cluster. Parent geometric error is the maximum propagated child/group error, not an independent estimate.
  4. Record why any excluded surface is legacy-only.
  5. Quantize and encode: quantized positions/normals/tangents/UVs and meshlet-local indices. Validate normal/UV seam behavior, tangent handedness, and double-sided flags against legacy renders.
  6. Build dependents: (a) a compact resident coarse renderer fallback inside VirtualGeometryData built from the root-level DAG cut per virtualized surface (without overwriting authored ArrayMesh surfaces under the default retain_authored mode; see §7.2), (b) a fixed import-time position-only proxy LOD for auxiliary captures and the post-v1 P5 RT tier (never a view-dependent cut), (c) editor bounds/preview metadata, and (d) Stage-2 per-cluster-group axis-dominant Surface Radiance Cache card descriptors upgrading P0/P1’s Stage-1 6-card surface bounds (§8.3). Collision/navigation shapes remain built from full authored geometry and do not read streamed pages.

7.3 Runtime storage, streaming, and culling

  • GPU arenas: new virtual_mesh_storage owns paged vertex/index arenas, cluster records, instance records, page table, free lists, and upload staging. Shared residency belongs in storage singletons, not a viewport-local structure.
  • Feedback loop: cull computes a wanted-page bitset/queue. A CPU/IO subsystem modeled on TextureStreaming prioritizes visible/front-to-back pages, enforces a project VRAM budget, decompresses on worker threads, and uploads with bounded per-frame work. Resident parents (and if roots are pending, the embedded coarse fallback in VirtualGeometryData) render until children arrive.
  • Cut selection: compute pass tests instance frustum, screen-projected cluster error, cone/backface criteria, residency, and per-surface eligibility. Error metric must be monotonic down the DAG so a crack-free cut exists.
  • GPU Hi-Z: build a depth pyramid from rendered depth; use two-phase occlusion (draw previously visible, build Hi-Z, cull/draw newly visible) to avoid one-frame holes. This replaces—not extends—the CPU baked-occluder path for virtual content.
  • Compaction: compact surviving clusters into indirect indexed draws. Phase 0 plumbs indirect-count through RenderingDevice/graph and consolidates Vulkan 1.2 drawIndirectCount; without driver support (Metal pre-ICB), use a bounded max count and measure empty-draw cost.
  • Explicit auxiliary-view policy: directional/positional shadow splits/faces run coarser dedicated cluster cuts; auxiliary INSTANCE_GEOMETRY_MASK renders — including GPUParticlesCollisionHeightField3D orthographic heightfield captures, ReflectionProbe updates, SDF/voxelizations, and custom material captures — draw the resident coarse fallback/fixed proxy from VirtualGeometryData rather than multiplying full cluster-cut passes or forcing full legacy GPU buffer uploads.

7.4 Visibility and material resolve

  • Hardware-rasterize clusters through a vertex shader that pulls cluster vertices from storage buffers. Write depth, velocity-compatible previous clip data (into the Step-1 pre-cleared velocity target preserved by load_color = true and skipping the :2327-2330 clear in Step 7), and a packed visibility ID. Software raster for subpixel triangles is a P0b experiment, not a v1 assumption.
  • Per-cluster draw identity is a P0b decision (with a hard Metal constraint): Vulkan currently leaves shaderDrawParameters disabled and no renderer shader uses gl_DrawID/gl_BaseInstance; D3D12’s shader-container mode zeros base-instance system values; and Metal’s MDCommandBuffer::render_draw_indexed_indirect (metal3_objects.cpp:1506-1521) is a CPU per-draw loop while render_draw_indexed_indirect_count (:1523-1525) is unimplemented. Consequently, only option (b) — a single-draw compute-expanded index/vertex stream carrying cluster ID — is portable to current Metal without P6 ICB driver work. P0b benchmarks (a) indirect-count multi-draw with shaderDrawParameters against (b) single-draw compute-expanded streams on Vulkan (RTX 4080 SUPER) and Metal (M5 Max).
  • Two-stage compute resolve (binding-model-neutral until P0b freezes §9): Stage A (before NextGI and Step 3b SSAO/SSCS/SSR) decodes visible triangles, reconstructs barycentrics and analytic/quad derivatives, fetches vertex attributes, and evaluates the GPU material record — using either Option A’s RD bindless descriptor table or Option B’s per-material classified compute dispatches — to populate albedo/normal/roughness guides; Stage B (after SVGF and _update_volumetric_fog) shades clustered direct lights/shadows, applies SSAO/SSCS, adds denoised NextGI diffuse/specular outputs, and premultiplies 3D fog_map.
  • Derivatives are a contract, not a detail: normal maps, anisotropy-like filtering, alpha edges, and texture LOD need analytic or quad-based derivative reconstruction and tests.
  • Alpha-scissor/hash content is excluded until material evaluation can discard during visibility and any-hit/shadow paths. Blended content, stencil overlays, next_pass, wireframe/points, and priority overlaps remain forward after resolve.
  • Custom vertex() that displaces or overrides position/projection invalidates offline bounds and therefore forces legacy rendering. Custom fragment() or light() forces per-surface legacy rendering unless it uses a documented, separately compiled supported subset.

7.5 Shadows, proxies, and interaction

  • v1 shadow views select a coarser cluster cut per virtualized (instance, surface, view) — dispatched before _render_shadow_begin/_render_shadow_end batch draw lists (render_forward_clustered.cpp:1665-1686) — while writing current shadow atlases alongside legacy shadow casters. Fixed atlas resolution and four directional splits still cap shadow sharpness until Virtual Shadow Maps land in P6.
  • Virtual Shadow Maps are Phase 6 because page allocation, invalidation by light/view/residency, and cluster cuts per shadow page are a system of their own.
  • RT proxy (post-v1 P5, plus P0’s legacy-mesh comparator) is one fixed import-time coarse proxy LOD per mesh — a position-only BLAS source with a stable triangle budget, never the view-dependent raster cut. Legacy-mesh BLAS building also adds acceleration-structure vertex/index usage flags in MeshStorage::mesh_add_surface that current upload omits.
  • Physics raycasts, navigation, CSG, LightmapGI::bake, and editor picking do not consume streamed GPU pages in v1. Under default retain_authored they consume intact authored ArrayMesh surfaces/collision shapes, and debug views surface when opt-in strip_authored_to_coarse is active.

8.2 Software SDF tier

  • Reuse SDFGI cascade infrastructure where contracts match — scrolling, JFA distance generation, probe history buffers, and half-resolution output plumbing — while replacing SDFGI’s camera-scroll-only / FLAG_USES_BAKED_LIGHT-only region capture with an AABB dirty-brick/region queue dispatched from RendererSceneCull.
  • Do not assume current 128³ R8 cascades are sufficient for near-field tracing. P1 benchmarks cascade resolution/bias and decides whether to keep runtime sparse cascades, add import-time mesh SDFs, or combine them. Runtime generation handles dynamic geometry directly under a voxelization budget; import-time mesh SDFs require an asset pipeline plus dynamic-instance composition.
  • SDF hits fetch material/radiance from the Surface Radiance Cache, never albedo guessed from position. Supported StandardMaterial3D surfaces shade cards via GPU material records; custom materials use a budgeted MODE_RENDER_MATERIAL-style raster capture into card pages as a compatibility path.
  • Thin/one-sided geometry is a first-class failure mode. Thickness/bias rules, probe relocation/occlusion, and sealed-room leak checks (§2’s ≤5% ceiling) belong in the solver and debug UI, not a troubleshooting footnote.

8.3 Two caches, per-instance radiance pages, and swept invalidation

v1 uses two distinct caches budgeted separately. Both parameterizations below are concrete candidates tested in P0a’s end-to-end NextGI spike (§17 item 8) without waiting for P2’s DAG importer or P0b’s material-binding benchmark.

  • Surface Radiance Cache (SRC) — per-mesh descriptors, budgeted per-instance radiance pages:
    • Per-mesh card descriptors (two-stage): Stage 1 (P0a spike, P1, and legacy-fallback meshes) builds card descriptors per eligible ArrayMesh surface at upload — 6 outer OBB/AABB cards for convex/solid meshes, extended to multi-box/normal-clustered interior cards whenever single-mesh concave interiors (rooms, courtyards, U-shapes) drop below §2’s ≥85% card-hit coverage threshold (since 6 outer AABB faces cannot see inward-facing walls of a single-mesh room). Stage 2 (P2 NextGeo upgrade) emits tighter per-cluster-group axis-dominant card descriptors inside VirtualGeometryData.
    • Per-instance radiance pages & eviction budget: outgoing radiance depends on each instance’s world transform, local lighting/shadows, and per-surface material overrides, so radiance atlas pages are allocated per active instance, never shared per mesh. Under a fixed SRC atlas VRAM budget (e.g., 4k×4k / 64–128 MiB across 128×128–32×32 tiles), instances are scored by screen solid angle and camera distance: near instances claim higher-res pages, mid-distance instances drop page mip resolution, and tiny/far or evicted instances in heavily instanced scenes (Dense City Blocks) release pages via LRU and fall back cleanly to WRC probes.
    • Card capture & shading: P0a’s spike (and v1’s custom-material compatibility path) reuses existing _render_material (render_forward_clustered.cpp:3061) to rasterize albedo/normal/roughness/emission into card pages and _render_sdfgi (:3203) for voxelization, decoupling P0a/P1 from P0b’s Option A/B material-binding choice. Direct lights, shadow atlases, sky, and second-bounce feedback are evaluated into dirty/scheduled instance pages at NextGI’s dedicated post-bake_cluster call site (§6.1 Step 5).
  • World Radiance Cache (WRC) — terminates paths: camera-centered clipmap of irradiance probes (octahedral/SH hybrid reusing SDFGI probe history where contracts fit), updated under a fixed per-frame ray budget. It supplies far-field, off-screen, and second-bounce radiance and serves as fallback when SRC coverage or instance page budget misses.
  • Bounce and energy model (v1): one explicit traced diffuse bounce shaded by SRC; further bounces enter through temporally accumulated SRC/WRC feedback with demodulated albedo, feedback gain <1.0, and a shared firefly/max-radiance clamp, validated against §2’s ≤20% diffuse radiance error bound vs LightmapGI / path-traced reference so an energy-biased solver cannot pass by converging to its own wrong static value. Specular uses one traced bounce terminating in SRC/WRC/sky.
  • Swept geometry, shadow, and region-cull invalidation (new work): (1) Snapshotted previous + current AABBs: RendererSceneCull::_update_instance overwrites Instance::prev_transformed_aabb (renderer_scene_cull.h:448; renderer_scene_cull.cpp:1772, 1945), so NextGI snapshots the pre-change world AABB when transform, visibility, mesh, material, emissive, or deletion dirty events fire, dirtying both boxes across affected SDF cascades, per-instance SRC pages, and WRC probes so moving geometry (e.g., an opening door) never leaves phantom SDF occlusion in vacated space. (2) Static-receiver shadow invalidation: when a shadow-casting occluder moves, its swept volume (prev_transformed_aabb ∪ transformed_aabb) is projected along active directional-light directions and intersecting local-light frustums/radii (clipped to active NextGI cascades) to mark newly lit/shadowed static-receiver instance SRC pages and WRC probes dirty, backed by a bounded background SRC refresh ring (1/16–1/32 of resident active pages per frame) so indirect bounce on static walls converges within §2’s 10-frame target. (3) RendererSceneCull dispatch: extend RendererSceneCull::_render_scene beyond camera-scroll sdfgi_get_pending_region_count and FLAG_USES_BAKED_LIGHT so arbitrary dirty world-AABB regions cull both static and dynamic GI-contributing opaque instances under a bounded per-frame brick budget. Animated TIME materials are flagged by shader analysis and excluded from static SRC caching.
  • Clean-room boundary: card/clipmap concepts come from public documentation and talks listed in §20; no card constants, layouts, or shader code are copied from any proprietary engine.

8.4 Hardware RT tier (post-v1 P5; P0 comparator only)

  • Target Vulkan non-Apple first (after P0 fixes RenderingDeviceDriverVulkan::acceleration_structure_instance_write to use vkGetAccelerationStructureDeviceAddressKHR). Build one static BLAS per mesh from the fixed import-time position-only NextGeo proxy LOD (§7.1, §7.5 — never a view-dependent raster cut) and from supported legacy static meshes (adding acceleration-structure vertex/index buffer usage flags in MeshStorage::mesh_add_surface); build/update TLAS from scene instances. Because the Vulkan path is triangles-only and build-only, dynamic/skinned geometry is excluded or rebuild-budgeted.
  • Use ray query in compute for probe/reflection traces. Full RT pipelines and hit shaders remain deferred unless ray-query compute fails P0/P5 gates.
  • HWRT direct hit shading requires position/normal/UV interpolation, texture derivatives, unified GPU material/texture lookup (Option A bindless descriptors or hit-classified shade queues), alpha policy, and emissive sampling. It is a P5 quality option, not a free replacement for SRC/WRC caching.
  • D3D12 DXR (including fixing SPIRV_TO_MESA_STAGES ray-stage mapping in rendering_shader_container_d3d12.cpp) and Metal acceleration structures are separate P6 driver implementations after the Vulkan vertical slice.

8.5 Final gather, reflections, and fog

  • Screen probes are placed on visible surfaces using Stage A / legacy prepass depth/normal/roughness guides, importance-sampled with previous-frame lighting, filtered spatially/temporally, then bilaterally upsampled.
  • When NextGI is active, disable SSIL automatically to prevent double-counting, while extending RenderForwardClustered’s previous-frame color-pyramid allocation and post-opaque mip copy to using_ssil || using_ssr || using_nextgi so §8.1’s screen traces retain lit color history even when SSR is off. Keep SSAO as contact detail only after energy tests confirm zero double-darkening.
  • Reflections use screen trace first, then SDF + SRC/WRC traces in v1 (and HWRT traces in P5). Reflection probes remain fallback for misses and unsupported tiers.
  • NextGI writes its low-resolution ambient volume (ambient_texture/gi_inject) before _update_volumetric_fog in §6.1 Step 5, which in turn runs before Stage B lighting resolve (Step 6) and legacy PASS_MODE_COLOR (Step 7) so 3D fog_map scattering and transmittance match across virtual and legacy opaque pixels.
  • Emissive surfaces contribute through GPU material records and SRC entries, governed by a shared intensity clamp/firefly policy with SVGF.

8.6 SVGF-class denoiser

Allocate persistent current/previous albedo, normal/roughness, linear depth, velocity, demodulated diffuse/specular, first/second moments, variance, and history length. Force depth + normal-roughness prepass and velocity generation whenever NextGI is enabled (pre-clearing velocity in §6.1 Step 1, running Step 7 PASS_MODE_COLOR with load_color = true / RD::DRAW_DEFAULT_ALL, and skipping the render_forward_clustered.cpp:2327-2330 velocity clear when virtual geometry drew — verified on both desktop Vulkan and Apple Metal TBDR so FSR2/TAA never receives discarded LOAD_OP_DONT_CARE motion vectors).

  • Temporal accumulation with disocclusion rejection from depth, normal, and mesh/surface/material ID changes.
  • Variance-guided spatial filtering; separate kernels/radii for diffuse and specular.
  • Firefly clamp before temporal accumulation; blue-noise/low-discrepancy sample rotation beyond current TAA jitter.
  • Explicit transparent, particle, skinned, and first-frame policies. Those pixels use probe/legacy GI rather than invalid history.
  • Debug views for raw signal, variance, history length, rejected history, and denoised output are required deliverables, not developer-only hacks.

9. Shared foundations

RenderingDevice and graph

  • Plumb indirect-count from driver through RenderingDevice, graph resource tracking, and binds. In Vulkan, consolidate standalone KHR structs into VkPhysicalDeviceVulkan12Features (VUID-VkDeviceCreateInfo-pNext-02830) to enable drawIndirectCount cleanly alongside existing BDA/Float16Int8/MemoryModel features, and fix acceleration_structure_instance_write to load/call vkGetAccelerationStructureDeviceAddressKHR. Metal needs indirect command buffers or compute-compacted emulation.
  • Add capability flags for indirect-count, draw-parameters/cluster-ID path, image atomics strategy, ray query, RT pipeline, and later mesh shaders. Renderer code must query and fall back, never hard-fail on software or headless drivers.
  • Add BLAS update/compaction only when a measured dynamic workload in P5/P6 needs it. Do not widen the API speculatively in P1.
  • Every new command needs graph usages/barriers and dummy-driver behavior; bypassing the graph loses the safety model.

Persistent GPU scene

  • Convert per-frame CPU instance submission into incrementally updated GPU instance/surface records for virtual content, while retaining current lists for legacy content and excluded sibling surfaces during migration.
  • Track both transformed_aabb and dirty-event-snapshotted prev_transformed_aabb (captured before RendererSceneCull::_update_instance overwrites it) plus stable IDs across frames for swept NextGI invalidation, per-instance SRC page tables, temporal history, streaming priority, post-v1 TLAS instances, and debug picking.
  • Free-list/compaction policy must handle scene unload, mesh replacement, skeleton changes, and editor reimport without GPU dangling IDs or un-dirtied vacated AABBs.

Material binding — P0 decision between two models

  • Option A, RD bindless extension: runtime descriptor arrays with partial binding/update-after-bind. Today Vulkan 1.2 features are only queried (never chained via VkPhysicalDeviceVulkan12Features), RD has no bindless feature flag, and uniform_set_create’s _add_dependency cascade-frees dependents when any bound texture is freed — so a global table requires an epoch/deferred-free descriptor path plus D3D12 descriptor-heap and Metal argument-buffer mappings.
  • Option B, per-material classified dispatch: group visible clusters/pixels by material variant and run bounded Stage A/B compute dispatches reusing existing per-material uniform sets. No new descriptor model; cost scales with visible material count.
  • P0 benchmarks both on the material-equivalence matrix (§17 item 6) before committing §7.4/§11/§14 to either one. Under both options: GPU material records derive from BaseMaterial3D, texture residency cooperates with texture streaming, missing mips never sample invalid descriptors, and feature analysis is shared across eligibility, SRC capture, shadows, and editor warnings.

Editor and observability

  • Viewport debug modes: cluster cut/error, page residency, visibility IDs, per-surface fallback reasons, SDF, SRC cards, WRC probes, screen probes, variance/history, RT proxy.
  • Import panel shows source triangles, clusters, DAG depth, pages, .scn/.res vs .ngm disk split (retain_authored vs strip_authored_to_coarse), estimated VRAM, build time, excluded surfaces, and proxy triangle count.
  • Runtime profiler scopes and counters are part of each phase exit gate: drawn clusters, wanted/resident pages, trace counts, dirty AABB/SRC updates, denoise time, fallback opaque pixel percentage.
  • One test project, owned by this program, becomes the visual language for every decision. No screenshot from an ad-hoc scene counts as a gate.

19. Legal, naming, and clean-room protocol

This section is an engineering control, not legal advice. Obtain counsel before a commercial release or before accepting code from anyone with access to proprietary engine source.

  1. Names: ship systems as NextGI/NextGeo. Use “Lumen-class”/“Nanite-class” only as descriptive comparisons in internal planning; do not imply Epic affiliation or compatibility.
  2. Project-approved study inputs: public papers, official public documentation, conference talks, observed editor behavior/debug views, and permissively licensed source whose license has been recorded.
  3. Forbidden inputs: Unreal Engine source/shaders, copied constants/tables, decompiled binaries, proprietary SDK source under incompatible terms, and code generated by prompting a model to reproduce such source.
  4. Separation: contributors who have recently read relevant proprietary source should write behavior/spec notes from public sources, not implementation code for the same subsystem. Keep a source log per subsystem.
  5. Vendoring gate: every third-party file gets upstream URL, version/commit, license text, modifications, and NOTICE placement under Godot’s existing third-party conventions before merge.
  6. Asset gate: test scenes use original or clearly permissively licensed content with recorded provenance. No marketplace/demo assets from proprietary engines.
  7. Trademark gate: GodotNext remains clearly unofficial in repository description and release notes. Do not use Godot or Epic logos in a way that implies endorsement.
  8. Patent step: clean-room controls address copyright, not patents. Before any public release (not before P0), obtain a patent review of the virtual-geometry and GI techniques as implemented.
